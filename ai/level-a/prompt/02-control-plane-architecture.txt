1. CRITICAL INSTRUCTION
## DO NOT DESIGN FIRST — RESEARCH FIRST
======================================================================

Do NOT start by inventing the Control Plane.

First investigate how mature systems solve comparable problems.

Then identify architectural patterns.

Then identify candidate architectures.

Then compare them.

Then select the architecture.

Then design the Day-1 implementation.

The process MUST be:

    RESEARCH
       ↓
    IDENTIFY REQUIREMENTS
       ↓
    IDENTIFY CONTROL-PLANE PATTERNS
       ↓
    IDENTIFY CANDIDATE ARCHITECTURES
       ↓
    ARCHITECTURE SELECTION ANALYSIS
       ↓
    TRADE-OFF ANALYSIS
       ↓
    ATTEMPT TO FALSIFY THE LEADING OPTION
       ↓
    FINAL ARCHITECTURAL DECISION
       ↓
    DAY-1 DESIGN
       ↓
    SCALE DESIGN
       ↓
    ENTERPRISE EVOLUTION

The architecture must be the RESULT of this process.

======================================================================
2. PROJECT CONTEXT
======================================================================

We are building an enterprise AI agent platform primarily oriented toward
CRM / ERP workloads.

The platform will eventually manage:

- agents
- agent versions
- models
- model versions
- tools
- tool versions
- workflows
- policies
- tenants
- deployments
- evaluations
- configurations
- runtime environments
- resource allocations
- lifecycle state
- audit metadata

The Control Plane should eventually provide the management and governance
surface through which these resources can be defined, versioned,
validated, deployed, observed and controlled.

However:

THE CONTROL PLANE MUST NOT BECOME THE RUNTIME.

The Control Plane configures and governs.

The Runtime executes.

This boundary must be investigated, validated and precisely defined.
