======================================================================
1. PRIMARY OBJECTIVE
======================================================================

Design the complete Data Governance, Privacy and Compliance Architecture.

The architecture must answer:

WHAT DATA DOES THE PLATFORM PROCESS?

WHO OWNS IT?

WHO MAY ACCESS IT?

WHY IS IT BEING PROCESSED?

WHERE DOES IT COME FROM?

WHERE DOES IT GO?

HOW DOES IT PROPAGATE?

HOW LONG IS IT RETAINED?

HOW IS IT DELETED?

CAN A USER REQUEST DELETION?

CAN DATA BE EXPORTED?

CAN DATA BE CORRECTED?

CAN DATA BE ISOLATED BY TENANT?

CAN DATA ENTER MODEL CONTEXT?

CAN DATA ENTER MEMORY?

CAN DATA ENTER EVALUATION DATASETS?

CAN DATA BE SENT TO EXTERNAL SERVICES?

CAN DATA BE USED FOR TRAINING?

HOW CAN ALL OF THIS BE AUDITED?

11. PURPOSE LIMITATION
======================================================================

Every meaningful data category should have an explicit purpose.

Examples:

Conversation data
→ provide requested service.

Memory
→ personalize future interactions.

Telemetry
→ operate and debug the platform.

Evaluation data
→ measure system quality.

Audit
→ security/compliance.

Do not silently reuse one dataset for another purpose.

======================================================================
12. DATA MINIMIZATION
======================================================================

Determine the minimum data required for each operation.

Example:

Tool B does not necessarily need the entire conversation.

Agent B does not necessarily need all user memory.

Evaluation does not necessarily need raw production data.

Observability does not necessarily need raw prompts.

Determine minimization boundaries.
