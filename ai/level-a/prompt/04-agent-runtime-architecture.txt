======================================================================
1. PRIMARY OBJECTIVE
======================================================================

Design the Agent Runtime that executes agent tasks.

The runtime is responsible for turning:

    USER INTENT
        ↓
    AGENT CONFIGURATION
        ↓
    PLAN
        ↓
    EXECUTION
        ↓
    VERIFICATION
        ↓
    RESULT

into a reliable, observable, auditable and secure execution.

However, do NOT assume that this simple sequence is sufficient.

Research modern agent runtimes and determine the appropriate architecture.

======================================================================
2. MOST IMPORTANT INSTRUCTION
## RESEARCH FIRST — DESIGN SECOND
======================================================================

Do NOT begin by designing the runtime.

First research:

- modern agent architectures
- workflow engines
- durable execution
- state-machine architectures
- graph-based execution
- agent planning
- agent loops
- tool execution architectures
- LLM runtime patterns
- recovery mechanisms
- human-in-the-loop systems
- distributed execution

Then identify competing architectures.

Then compare them.

Then select the best architecture for THIS project.

Then attempt to disprove it.

Then design the runtime.

The required process is:

    RESEARCH
       ↓
    REQUIREMENTS
       ↓
    CANDIDATE RUNTIME ARCHITECTURES
       ↓
    ARCHITECTURE SELECTION ANALYSIS
       ↓
    TRADE-OFF ANALYSIS
       ↓
    ADVERSARIAL CHALLENGE
       ↓
    FINAL ARCHITECTURAL DECISION
       ↓
    DAY-1 IMPLEMENTATION
       ↓
    FUTURE EVOLUTION

The architecture must be the RESULT of the research.

3. DAY-1 CONSTRAINTS
======================================================================

The Day-1 runtime must operate on:

- one modest machine
- one GPU if available
- Qwen3.5 9B
- PostgreSQL
- local/containerized services
- limited CPU
- limited RAM
- limited VRAM
- small engineering team

There is NO mandatory:

- Kubernetes
- distributed scheduler
- distributed workflow engine
- service mesh
- multi-GPU runtime
- multiple inference workers
- cloud LLM
- distributed event bus
- multi-region
- microservice architecture

The runtime must remain understandable and debuggable by a small team.
