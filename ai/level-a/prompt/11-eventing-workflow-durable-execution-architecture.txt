6. WORKFLOW VS AGENT
======================================================================

This is one of the most important architectural decisions.

Compare:

Workflow:

A → B → C

with:

Agent:

Reason → decide → adapt → act.

Determine when a process should be:

- deterministic workflow
- agent-driven execution
- hybrid

Do NOT use an agent for deterministic orchestration merely because an LLM
can technically perform the orchestration.

======================================================================
7. WORKFLOW VS TOOL
======================================================================

Determine when a capability should be:

Tool

versus:

Workflow.

Example:

"Send email"

may be a Tool.

"Prepare monthly customer report → obtain approval → generate PDF →
send email → record completion"

may be a Workflow.

These are hypotheses.

Research and define objective boundaries.

15. PROCESS RESTART
======================================================================

Scenario:

Workflow is executing.

Machine crashes.

WHAT HAPPENS?

- whether the step completed
- whether retry is safe
- what authorization existed
- what outputs were produced.

16. IDEMPOTENCY
======================================================================

This is CRITICAL.

Example:

Agent calls:

"Create invoice."

Request succeeds.

Response is lost.

System retries.

A duplicate invoice must not be created.

Determine idempotency strategy.

Potential:

- idempotency key
- operation ID
- deduplication table
- external idempotency key
- transactional state.

======================================================================
17. EXACTLY-ONCE
======================================================================

"exactly once".

Research the semantics.

Determine whether the architecture actually provides:

- at-most-once
- at-least-once
- effectively-once through idempotency
- exactly-once under constrained conditions.

Use precise terminology.

28. SAGA / COMPENSATION
======================================================================

Long workflows may perform irreversible side effects.

Example:

1. Create CRM record.
2. Send email.
3. Create invoice.
4. Update ERP.

If step 4 fails, earlier actions may already exist.

Research:

- saga
- compensation
- rollback
- manual recovery.

Do not pretend external side effects can always be rolled back.
