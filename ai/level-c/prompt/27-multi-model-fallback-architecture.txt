1. MOST IMPORTANT INSTRUCTION
## CLAUDE MUST CHOOSE THE MULTI-MODEL ARCHITECTURE
======================================================================

This is NOT a prompt asking for a predetermined:

PRIMARY MODEL
+
BACKUP MODEL.

Claude MUST independently determine the best architecture for model
failure, degradation, substitution and fallback in THIS platform.

Do NOT begin by assuming:

- one primary model
- one secondary model
- round-robin routing
- load balancing
- automatic retries
- a specific model provider
- a specific inference engine
- a specific cloud
- a specific model router
- a specific gateway
- local inference
- multi-cloud.

These are candidate mechanisms.

They are NOT architectural conclusions.

Claude MUST first understand:

- what constitutes model failure
- what constitutes model degradation
- which failures are recoverable
- which failures require fallback
- which models are actually compatible
- what information can be transferred
- what information cannot be transferred
- which policies restrict fallback
- what quality loss is acceptable
- what safety constraints apply
- what compliance constraints apply
- what cost constraints apply
- what latency constraints apply
- what tenant requirements apply.

Only then select the architecture.

4. FALLBACK IS NOT ALWAYS THE CORRECT RESPONSE
======================================================================

A fallback can be worse than a controlled failure.

For every failure determine whether the correct action is:

- retry
- wait
- backoff
- circuit break
- fallback
- degrade functionality
- ask user
- human escalation
- reject request
- queue request
- load shed
- fail closed
- fail safe.

Do not automatically fallback.
