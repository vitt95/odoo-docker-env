3. CENTRAL PRINCIPLE
======================================================================

MCP IS A PROTOCOL.

MCP IS NOT THE PLATFORM.

Do not allow:

MCP

to become:

THE ARCHITECTURE.

The platform must maintain internal domain contracts independently
where doing so provides better:

- control
- security
- performance
- observability
- reliability
- versioning
- governance.

MCP should be treated as an INTEROPERABILITY BOUNDARY where it provides
real value.

======================================================================

This document is:

LEVEL C — SUCCESSIVE / FUTURE ECOSYSTEM CAPABILITY.

DO NOT make MCP a mandatory Day-1 dependency unless research proves
that a real Day-1 requirement cannot be satisfied otherwise.

ecosystem.

THE DAY-1 ARCHITECTURE MUST NOT MAKE FUTURE MCP ADOPTION DIFFICULT.
