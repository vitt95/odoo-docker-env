1. MOST IMPORTANT INSTRUCTION
## CLAUDE MUST CHOOSE THE HUMAN-OVERSIGHT ARCHITECTURE
======================================================================

This is NOT a prompt asking you to automatically add:

"human approval"

to every important agent action.

Claude MUST independently determine:

WHEN HUMAN INVOLVEMENT IS ACTUALLY NECESSARY.

WHEN HUMAN INVOLVEMENT IS NOT NECESSARY.

WHEN HUMAN INVOLVEMENT WOULD REDUCE RISK.

WHEN HUMAN INVOLVEMENT WOULD ACTUALLY INCREASE RISK.

WHEN HUMAN REVIEW SHOULD BE:

- preventive
- concurrent
- supervisory
- retrospective
- exception-based
- escalation-based.

Do NOT assume:

human = safer.

A poorly designed human approval system can create:

- approval fatigue
- automation bias
- rubber-stamping
- alert fatigue
- latency
- bottlenecks
- unclear accountability
- unauthorized delegation
- decision ambiguity.

Claude MUST analyze the complete platform and choose the best
human-oversight architecture available.

6. LEVEL
======================================================================

This document belongs to:

LEVEL C — SUCCESSIVE ARCHITECTURE.

The platform does NOT need sophisticated enterprise human-approval
workflows on Day 1 unless actual use cases require them.

However:

DAY 1 MUST NOT MAKE FUTURE HUMAN OVERSIGHT IMPOSSIBLE.

The Agent Runtime must therefore preserve stable concepts for:

- action identity
- decision identity
- authorization
- policy evaluation
- execution state
- approval state
- actor identity
- auditability.

Do not build a complete enterprise approval platform prematurely.

7. FUNDAMENTAL QUESTION
======================================================================

For every potentially consequential agent action ask:

CAN THIS ACTION BE SAFELY AUTOMATED?

If yes:

WHY?

If no:

WHY NOT?

If uncertain:

WHAT INFORMATION WOULD REDUCE THE UNCERTAINTY?

If human involvement is required:

WHAT EXACT HUMAN DECISION IS REQUIRED?
